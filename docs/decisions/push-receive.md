# プッシュの受信と、押したとき

- 状態：提案中
- 関連：[通知](notifications.md)（許可と登録、バッジ）、[UI とツール](ui.md)（5 の PWA）、[ローカルファースト](local-first.md)（1、3 の同期）、[ワークスペース](workspaces.md)（3 の範囲）、[画像](images.md)（3・4 のキャッシュ）、[コンテナ版](container.md)（3、5）、[記事の中の X の投稿](embeds.md)（3）、sendo の[通知](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/notifications.md)

sendo は、ベルに当たった新しい記事を Web Push で送る。通知の中身と形は、sendo の決定が正で、ここには書き写さない。reader は、Service Worker で通知を出し、押された通知の記事を開く。通知の許可と登録、アプリのバッジは、[通知](notifications.md)に書く。

## 決定

### Service Worker

1. **Service Worker は、vite-plugin-pwa の injectManifest で自分で書く。** push、`notificationclick`、`notificationclose` を受けるため。
   - Workbox の部品は import し、1 つのファイル（`sw.js`）にまとめる。`importScripts` は使わない。Service Worker も本番の CSP の下で動き、Trusted Types を強制しているので、`importScripts` に文字列を渡せない
   - 今の動きを保つ。アプリの外枠と SQLite の wasm の precache（`/version.json` は入れない）、ないパスに返す `index.html`（sendo のパスは `sendo-paths.ts` の一覧で除く。[コンテナ版](container.md)の 3）、画像のキャッシュ（[画像](images.md)の 3・4。消したあとに遅れて届いた画像を入れない世代の印を含む）、古いキャッシュの片付け、新しい版の取り込みと切り替え（[UI とツール](ui.md)の 5。取り込んだらすぐ使い始め、開いている画面を受け持つ）
   - precache の一覧は、injectManifest が差し込む形のまま `sw.js` に入れる。workbox-build が鍵を並べた JSON にするので、`index.html` の項目は `{"revision":"…","url":"index.html"}` になる。コンテナは、この形の `index.html` の版の印を書き換える（[コンテナ版](container.md)の 5、[記事の中の X の投稿](embeds.md)の 3）。generateSW の出力の形（`{url:"index.html",revision:"…"}`）は探さない
2. **push を受けたら、届いた中身で通知を出し直す。** 中身の形は sendo の[通知](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/notifications.md)の 14。
   - 宣言型の push（`web_push: 8030`）を読むブラウザーでは `event.notification` から、読まないブラウザーでは `event.data` の JSON の `notification` から読む
   - `showNotification` に、`title`、`body`、`tag`、`data` と、`navigate` を必ず渡す。宣言型の push で出し直すときに `navigate` がないと、例外になる。`navigate` には届いた値を使わず、`tag` の記事の ID（3）から、自分のオリジンの記事の URL（`/?article=<記事の ID>`。値は `URLSearchParams` で符号化する）を組み立てて渡す。`tag` を読めなければ、reader の先頭（`/`）を渡す
   - 中身が形に合わない（`title` か `tag` が文字列でない）ときは、宣言型の push では出し直さない（宣言した通知が出る）。読まないブラウザーでは、「Sendo」とだけ書いた通知を出し、押したら reader の先頭を開く
   - 出し終えてから、`tag` を覚える（4）
   - push の中では `setAppBadge` を呼ばない。バッジは、閉じている間は push の `app_badge` でブラウザーが書き、開いている間は画面が書く（[通知](notifications.md)の 5）
   - reader を開いていても、通知は出す

### 押したとき

3. **押したことが届いたら（`notificationclick`）、その記事を開く。** 記事の ID は `tag`（`bell:<ベルの ID>:<記事の ID>`）から読む。`bell:` の次の `:` までをベルの ID、残りを記事の ID とする。読めない `tag`（`bell:` で始まらない、どちらかの ID が空）なら、reader の先頭（`/`）を開く。iOS で取り直した通知は `data` が空になる。
   - 通知を閉じ、覚えた `tag` を外してから、開いている reader の画面を、最後に前に出ていたものから選ぶ。`/oauth/authorize` と、読み込み直すと消えるものを出している画面（[UI とツール](ui.md)の 5。発行したトークンを出す Settings など、パスで分かるもの）は選ばない
   - 選んだ画面に、開く記事の ID を知らせる。画面は、読み込み直すと消えるものを出していなければ（自動の読み込み直しと同じ条件。`reloadGuard` の印を含む）、受けたことを返し、読み込み直さずに `/?article=<記事の ID>` へ移る。記事の URL を開いたとき（5）と同じ道で開く。Service Worker は、受けたことが返ったら、その画面を前に出す
   - 選べる画面がない、断られた、0.5 秒のうちに受けたことが返らないときは、`clients.openWindow('/?article=<記事の ID>')` で開く
   - 知らせには送った時刻を入れ、画面は、受けたときに 0.3 秒より古い知らせを断る。画面が断る上限は、Service Worker が待つ時間（0.5 秒）より、受けたことの返事が届く分だけ短くする。Service Worker が新しい窓で開いたあとに遅れて届いた知らせで移ると、2 か所で開く
   - Service Worker と画面の間の知らせの形は変えない。変えるときは、別の名前の知らせにする（古い版の画面は答えず、新しい窓で開く）
   - reader を終了しているときは、通知の `navigate` の URL で reader が開く（iOS で `notificationclick` が来なくても、これで開く）。記事の URL を開いたのと同じに扱う
4. **iPhone と iPad のホーム画面のアプリ（`navigator.standalone === true` で、かつ触れる画面（`navigator.maxTouchPoints > 1`））で、裏で動いているときに押された通知は、通知センターから消えた通知で見分ける。** このときは reader が前に出るだけで、`notificationclick` も `navigate` も来ない。
   - Service Worker は、通知を出し終えたら、その `tag` と覚えた時刻を IndexedDB に覚える。`notificationclose`（利用者が消した）が来たら、その `tag` を外す（`notificationclick` は 3）
   - 画面は、前に出たとき（`visibilitychange` で `visible` になったとき）に `getNotifications()` で出ている通知を取り直し、覚えた `tag` のうち出ていないものを、消えたものとして覚えから外す。取り直し始めたあとに覚えた `tag` は比べない
   - 消えたのが 1 件なら、押されたものとみなして、その記事を 3 と同じく `/?article=<記事の ID>` へ移って開く。読み込み直すと消えるものを出している画面なら、開かない。2 件以上なら、どれも開かない
   - 起動したときは、消えた `tag` を外すだけで、開かない。終了しているときに押されたなら、`navigate` で開いている
   - 新しい版への切り替えで自動で読み込み直すとき（[UI とツール](ui.md)の 5）は、読み込み直す前に `sessionStorage` に印を置く（印には何も入れない）。読み込み直したあとの起動で印を見つけたら消し、前に出ていれば、起動ではなく前に出たときと同じに扱う。裏で起動したなら、次に前に出たときに、いつもどおり扱う
   - 前に出たときに、自動で読み込み直すと決めたら、その前に出たことでは消えた通知を比べない（読み込み直したあとの、印のある起動で比べる）。読み込み直すかを先に決め（[UI とツール](ui.md)の 5）、比べるのはその結果を見てからにする
   - ほかの環境でも、消えた `tag` は起動したときと前に出たときに外すが、開かない。押したことは `notificationclick` で届く
   - 横にスワイプして消した通知と押した通知は、`notificationclose` が来ないと見分けられない。裏に回している間に 1 件だけ消してから、ホーム画面のアイコンで reader を開くと、その記事が開いて既読になる。前に出ている間に消えた通知も、次に前に出たときに消えたものに数える。この誤りは許す
5. **通知から開いた記事が、まだ手元にないときは、記事の画面のまま同期を待つ。**
   - 同期を頼み（起動したときや前に出たときの同期と重なれば、まとまる。[ローカルファースト](local-first.md)の 3）、頼んだあとに始まった同期が終わるまでは「記事を同期しています…」と出し、届いたら記事を出す。同期が終わってもなければ（受信箱から消えた、sendo に届かない）、「この記事は手元にありません。」と出す。一覧には戻さない。そう出したあとに、あとの同期で届いたら、記事を出す
   - `navigate` で開いた URL は、記事の URL を直接開いたのと見分けないので、記事の URL を開いたときはいつもこうする
   - 選んでいるワークスペースの範囲の外の記事は、記事の URL を開いたときと同じく出さない（[ワークスペース](workspaces.md)の 3）。3 と 4 で開こうとした記事なら、「通知の記事は、選んでいるワークスペースに入っていないため、開きませんでした。」と、取り消しの知らせと同じ画面の下の知らせで出す。記事の名前は出さない。3 の `openWindow` で開いた新しい窓と `navigate` で開いたときは、記事の URL を開いたのと見分けないので、この知らせは出ない

### 通知の中身

6. **通知の中身は、Service Worker が通知に出すだけにする。**
   - `title` と `body` は、届いた文字をそのまま `showNotification` に渡す。HTML として組み立てず、手も加えない（長さは sendo が切る。sendo の[通知](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/notifications.md)の 15・16）
   - 中身を、手元の DB、IndexedDB、ログ（失敗したときも）、Service Worker のキャッシュに残さない。画面にも渡さない。開く記事は ID で決め、出すのは手元の DB の記事
   - IndexedDB に覚えるのは、`tag`（ベルと記事の ID）と覚えた時刻だけ。ログアウトとユーザーの切り替えで消す（[通知](notifications.md)の 4）
   - IndexedDB のデータベースは、Service Worker と画面の両方が開く。形を変えるときに備え、どの接続も `versionchange` を受けたら閉じる

## 理由

- **injectManifest**：generateSW の Service Worker に push の処理を足すには `importScripts` が要り、Trusted Types で止まる。自分で書くと、画像のキャッシュの世代の印の名前のように、画面と Service Worker の両方が使うものを、ほかのコードと同じく import で分け合える。generateSW では、設定に文字のまま書き写すことになる。
- **通知を出し直す**：宣言型の push を読まないブラウザー（Chrome など）では、Service Worker が出すしかない。宣言型を読むブラウザーでも同じ道で出せば、書き方が 1 つで済み、出した通知の `tag` を覚えられる。試作で、裏で動いているときに押された記事を開けたのは、Service Worker が出した通知だった。出し直しに失敗しても、宣言した通知が出る（`mutable`）。
- **`navigate` を組み立てる**：届いた値をそのまま渡すと、記事の URL でない URL で reader を開きうる。`tag` の記事の ID から組み立てれば、開くのは自分のオリジンの記事の URL か先頭だけになる。
- **開いていても通知を出す**：`userVisibleOnly` の登録は、push のたびに通知を出す約束で、出さないと、ブラウザーが代わりの通知を出すか、出さない push に数えて登録を消す（iOS は 3 回で消す）。
- **push の中で `setAppBadge` を呼ばない**：iOS では、宣言型の push の中で呼ぶと promise が返らず、push が時間切れになって通知ごと出ない（試作）。
- **`tag` で見分け、IndexedDB に覚える**：iOS で通知センターから取り直した通知では `data` が空で、`tag` は残る。試作で、Cache Storage は Service Worker の書き込みが画面から見えなかったが、IndexedDB の書き込みは見えた。覚えるのを `tag` と時刻だけにすれば、手元に記事のタイトルが残らない。
- **開いている画面に記事を開かせる**：新しい窓で開くと、同じ reader の画面が増える。読み込み直すと消えるものを出している画面を移すと、発行したトークンや OAuth の許可の途中が消えるので、自動の読み込み直しと同じ条件で除く。答えを短い間だけ待つのは、押したことを受けてから少しの間しか、窓を開くことと前に出すことを許さないブラウザーがあるため。答えない画面（古い版、止まっている）があっても、新しい窓で開ける。古い知らせを画面が断るのは、待つのをやめて新しい窓で開いたあとに、遅れて受けた画面まで移らないようにするため。
- **画面が断る上限を、Service Worker が待つ時間より短くする**：同じ時間にすると、上限の間際に知らせを受けて移った画面の返事が、Service Worker が待つのをやめたあとに届き、Service Worker も新しい窓で開く。往復の分だけ短くすれば、画面が移るなら、Service Worker はその返事を待つうちに受けられる。
- **iPhone と iPad のホーム画面のアプリでだけ、消えた通知で開く**：押したことが届かないのは、そこで確かめた WebKit の不具合（bug 282935）。押したことが届く環境で消えた通知を数えると、OS が古い通知を片付けたときなどに、押していない記事を開く。試作で確かめたのは iPhone（iOS 27.2）のホーム画面のアプリだけで、iPad と macOS の Safari は確かめていない。
- **消えた通知で開く環境を、触れる画面でも絞る**：macOS の Safari の Dock のウェブアプリが `navigator.standalone` を true で返すなら、`notificationclick` が届くのに消えた通知でも開き、3 と 4 が同じ記事を 2 度開こうとする。iPhone と iPad は触れる画面なので、`navigator.maxTouchPoints` も見る。
- **1 件なら開き、2 件以上なら開かない**：記事を開くと既読になるので、取り違えると、押していない記事を既読にする。1 件だけ消えるのはたいてい押したときで、1 件だけスワイプで消してからアイコンで開くことは少ない。取り違えても、未読に戻せる。2 件以上消えるのは、まとめて消してからアイコンで開いたときが多く、どれも押していないことが多い。
- **起動したときは開かない**：終了していたなら、押した記事は `navigate` が開いている。消えた通知で開くと、アイコンで起動したときに、消しただけの通知の記事まで開く。
- **版の切り替えで読み込み直したあとは、前に出たときと同じに扱う**：新しい版を待っている画面は、裏に回ったときと前に出たときに読み込み直す（[UI とツール](ui.md)の 5）。押した通知で前に出たときに読み込み直すと、そのあとの画面は起動として扱われ、押した記事が開かない。裏に回ったときの読み込み直しも、前に出るまで終わらなければ同じになる。印を 1 つ置けば、どちらも、いつもの比べ方で決められる。読み込み直すと決めた前に出たことで比べないのは、比べ終える前に読み込み直しが始まると、消えた `tag` を外したまま記事を開かずに終わり、読み込み直したあとの起動で比べるものが残らないため。
- **出し終えてから覚え、取り直し始めたあとの `tag` は比べない**：先に覚えると、出せなかった通知を、消えた（押された）ものと取り違える。前に出たのと同じころに届いた通知も、比べると、まだ取り直しに入っていないだけで消えたように見える。
- **記事の画面で同期を待つ**：sendo は受信箱に配ってから通知を送るので、通知が届いたときには記事が sendo にあり、前に出たときの同期ですぐ届く。一覧に戻すと、押した記事を探し直すことになる。sendo から記事を直接取ると、画面がネットワークを待つことになる（[ローカルファースト](local-first.md)の 1）。
- **範囲の外の記事は開かない**：開くと、通知を押すだけでワークスペースの範囲が広がり、画面を共有している間に範囲の外の記事が出る。知らせるのは、押したのに何も起きないように見えないため。通知そのものにタイトルが出ているので、知らせても、新しく見えるものはない。

## 検討した代替案

- **generateSW のまま、push の処理を `importScripts` で足す**：今の設定を変えずに済むが、Trusted Types で止まる。
- **宣言した通知をそのまま出し、Service Worker は `tag` を覚えるだけにする**：出し直さずに済むが、宣言型を読まないブラウザーには別の道が要る。宣言したまま出た通知を `getNotifications()` で取り直せるかは、確かめていない。
- **宣言型を読まないブラウザーでだけ、push の中で `setAppBadge` を呼ぶ**：Chrome でも閉じている間にバッジが変わるが、ブラウザーで道が分かれ、見分けを誤ると iOS で通知ごと出なくなる。
- **記事の ID を `data` だけから読む**：iOS で取り直すと消える。
- **押された記事を Cache Storage に覚える**：試作で、Service Worker の書き込みが画面から見えなかった。
- **押したら、いつも新しい窓で開く**：画面に知らせる形が要らないが、開いている画面が残ったまま、同じ reader の窓が増える。
- **Service Worker と画面の間の知らせに、版の番号を付ける**：形を変えても同じ名前で送れるが、番号を比べる処理が要る。名前を替えれば、古い画面は答えず、新しい窓で開くだけで済む。
- **裏で動いているときは前に出すだけにし、記事を開かない**：取り違えはないが、iOS で通知を押しても記事が開かない。
- **2 件以上消えたら、いちばん新しい通知の記事を開く**：押したのがそれなら開けるが、違えば押していない記事を既読にする。
- **2 件以上消えたら、消えた通知の記事を並べた一覧を出す**：選び直せるが、通知のための一覧の画面と、その記事を覚える場所が要る。
- **どの環境でも、消えた通知で開く**：作りは 1 つで済むが、押したことが届く環境で、OS が片付けた通知の記事を開く。
- **版の切り替えで読み込み直す前に、消えた通知を確かめ、開く記事があれば移ってから読み込み直す**：印が要らないが、裏に回ったときに読み込み直し、前に出るまで終わらなかった画面は救えない（確かめた時点では、まだ押されていない）。
- **記事がないときは、一覧に戻す**：待たせないが、押した記事を探し直すことになる。
- **記事がないときは、sendo から記事を取って出す**：すぐ出せるが、画面がネットワークを待ち、手元の DB にない記事を出す道が増える。
- **範囲の外の記事なら、All に切り替えて開く**：押した記事が必ず出るが、画面を共有している間に、通知を押すと範囲が広がる。
- **通知の中身を手元に置き、通知の一覧を出す**：あとから見返せるが、記事のタイトルが手元に残り、受信箱の一覧と役目が重なる。

## 見直す条件

- iOS で、裏で動いているホーム画面のアプリにも `notificationclick` か `navigate` が届くようになったとき（WebKit bug 282935）。消えた通知で見分けるのをやめる。
- スワイプで消しただけの記事が開く、という声が続いたとき。iOS が `notificationclose` を送ると分かったとき。
- iPad や macOS の Safari で、押した通知の記事が開かない、取り違える、と分かったとき（試作は iPhone だけ）。
- 宣言型の push を読むブラウザーが変わったとき、push の中で `setAppBadge` が返るようになったとき。閉じている間のバッジの書き方を決め直す。
- sendo の通知の形（`tag`、`navigate`、`app_badge`）が変わったとき。
- reader が記事を開く URL（`/?article=<記事の ID>`）を変えるとき。sendo の `navigate` と Service Worker が組み立てる URL を合わせ、通知センターに残った古い URL も開けるようにする。
