# 設定の同期

- 状態：提案中
- 関連：[ローカルファースト](local-first.md)（決定の 2・4・6）、[UI とツール](ui.md)、sendo の[クライアントの設定](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/settings.md)・[差分同期](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/sync.md)

表示の設定（テーマ、文字の大きさ、一覧の並び順、スワイプの割り当てなど）を、sendo に預けて、同じ人のほかの端末に引き継ぐ。スマホと PC では合う設定が違うので、端末の種類（`mobile` ／ `desktop`）ごとに分ける。

預かり方（項目ごとの行、後から受けたほうを採る、上限、API の形）は、sendo の決定が正で、ここには書き写さない。ここでは、reader の側の決まり（端末の種類の決め方、項目の名前、手元の置き方、送り方、移行）を決める。

## 決定

### 端末の種類

1. **スマホは `mobile`、それ以外（PC、タブレット）は `desktop`。**
   - `mobile` は、主な入力が指（`pointer: coarse`）で、画面の短い辺が 600px（CSS の px）より小さい端末。画面（`screen`）の大きさで決めるので、ウィンドウの幅を変えても、端末を回しても変わらない
   - 起動のたびに決める。手元には覚えない（決め方を変えたら、次の起動から変わる）
   - 利用者が種類を選ぶ画面は置かない

### 項目

2. **名前は `reader.` で始め、別々に変わるものは別の項目にする。** 同じ項目を 2 台が変えたら、sendo が後から受けたほうになるので、1 つの項目には、一緒に変わるものだけを入れる。

   | 名前 | 値 | 既定 |
   |---|---|---|
   | `reader.theme` | `"auto"` ／ `"light"` ／ `"dark"` | `"auto"` |
   | `reader.textSize` | `"xsmall"` ／ `"small"` ／ `"medium"` ／ `"large"` ／ `"xlarge"`（小さい順の 5 段） | `"medium"` |
   | `reader.unreadOnly` | 真偽（未読だけを出す、の既定） | `true` |
   | `reader.oldestFirst` | 真偽（古い順に並べる、の既定） | `false` |
   | `reader.markReadOnScroll` | 真偽 | `true` |
   | `reader.hideReadFeeds` | 真偽 | `false` |
   | `reader.collapsed` | 畳んでいるフォルダの ID の配列（200 個まで） | `[]` |
   | `reader.swipe.listLeft` ／ `listRight` | `"none"` ／ `"read"` ／ `"star"` | `"read"` ／ `"star"` |
   | `reader.swipe.articleLeft` ／ `articleRight` | `"none"` ／ `"back"` ／ `"next"` ／ `"previous"` | `"none"` ／ `"back"` |
   | `reader.list:<一覧のパス>` | その一覧で変えたもの（`unreadOnly`・`oldestFirst` のうち、変えたものだけ） | なし |

   - **「未読」は、一覧の絞り込みの状態で、一覧の種類ではない。** 未読だけを集めた別の画面は持たない。どの一覧（All、フォルダ、フィード）も、未読だけを出すか、既読も出すかを、同じ切り替えで選ぶ。既定は、未読だけ
   - **既定と同じ値は、預けない。** 既定に戻したら、項目を消す（`remove`）。既定を変えたとき、変えていない人には新しい既定が当たる
   - 一覧ごとの設定は、一覧 1 つにつき 1 項目（`reader.list:/feeds/<id>` など）。名前に使えない一覧のパス（ASCII でない、長すぎる）の設定は、預けない
   - 読むときは、値の形を確かめる。知らない値や壊れた値は、既定として扱う（新しい版の reader が置いた値を、古い版が読んでも壊れない）
   - 頻繁に変わるもの（スクロールの位置、最後に開いた一覧）は、入れない
3. **購読をやめたら、そのフィードの一覧の設定を消す。フォルダを消したときも同じ。** sendo は名前を解釈しないので、消すのは reader の仕事。
   - 両方の種類（`mobile` と `desktop`）の項目を消す。ない項目を消しても、何も起きない
   - この reader でやめたときにだけ消す。ほかのクライアントでやめた購読の分は残る（上限に対して小さいので、探して消すことはしない）

### 手元の置き方

4. **手元の DB に、端末の種類・名前・値で置く。画面は、手元だけを読む。**
   - 同期で届いた `settings` を、両方の種類とも置く。使うのは、自分の種類の分だけ
   - 消した印（`deleted: true`）が届いたら、その項目を消す（既定に戻る）
   - 知らない端末の種類の項目は、置かない
   - `settings` のない応答（設定を配る前の版の sendo）でも、同期は止めない
5. **起動してすぐ当てるための写しを、localStorage に置く。** テーマと文字の大きさは、DB のワーカーを待たずに当てたい（待つと、起動のたびに色が切り替わって見える）。
   - 写しは、手元の DB から読んだ設定で、そのつど置き直す。正は手元の DB で、写しから DB には戻さない
   - ログアウトしたとき、ユーザーが替わったときは、写しも消す

### 送り方

6. **設定を変えたら、手元にすぐ反映して、操作キューに積む。** ほかの操作と同じ（[ローカルファースト](local-first.md)の 4）。
   - 手元への反映と、キューに積むのは、同じトランザクション
   - 送るのは `PATCH /api/v1/settings/{deviceType}`。置く項目と消す項目を、まとめて送る
   - 列の最後が同じ種類の設定の操作なら、まとめる。同じ名前は、最後の操作だけを残す。まとめた結果が 100 項目を超えたら、100 項目ずつに分けて送る（何度送り直しても同じ結果になる）
   - まだ送っていない変更のある項目は、同期で届いた値で上書きしない（届いた行の上に、操作を重ね直す）
7. **sendo が受け付けなかった変更は、送り直さず、手元を sendo の状態に戻して捨てる。** 400（名前や値の形）と 409（`settings_full`：数や合計の上限）は、送り直しても通らない。
   - 戻すときは、`GET /api/v1/settings/{deviceType}` で今の値を読み、その操作が触った項目を置き直す。読むのは、このときだけ
   - 5xx、通信の失敗、セッション切れは、ほかの操作と同じく、残して送り直す
8. **最初から同期し直すときは、手元の設定を、届いたもので置き換える。** まだ送っていない変更は、その上に重ね直す。

### localStorage からの移行

9. **前の版が localStorage に置いた設定は、先に同期してから、sendo にない項目だけを送る。** そのまま全部送ると、ほかの端末が置いた設定を上書きする。
   - 起動したとき（ログインしているとき）に、前の設定を項目に直し（既定と同じ値は除く）、「移行待ち」として手元の DB に置く。置けたら、localStorage の前の設定は消す
   - 移行待ちの項目は、手元にその名前の項目がない間、設定として使う（移行が済むまでの間に、見た目が既定に戻らない）
   - 同期を最後まで終えたときに、移行待ちのうち、sendo から届いていない名前だけを、操作キューに積む。届いている名前は、届いたほうを採る。そのあと、移行待ちを消す
   - `settings` のない応答（前の版の sendo）では、移行を進めない（移行待ちのまま残す）

## 理由

- **スマホだけを `mobile` にする**：分けたいのは「片手で持って指で使う小さな画面」と、それ以外。タブレットは、画面の作りも PC と同じにしている。ウィンドウの幅で決めると、PC でウィンドウを狭めたときに設定が入れ替わる。
- **種類を手元に覚えない**：覚えると、決め方を直しても古い端末に当たらない。両方の種類の設定が手元にあるので、種類が変わっても、同期し直さずに切り替わる。
- **項目を細かく分ける**：テーマとスワイプの割り当てを 1 つの値にまとめると、2 台で別々のものを変えたときに、片方が消える。sendo の上限（1,000 項目）に対して、決まった項目は十数個。
- **未読を、絞り込みにする**：「未読」と「すべて」を別の画面にすると、同じ記事の集まりに入口が 2 つでき、フォルダやフィードの一覧（切り替えで選ぶ）と作りが揃わない。Feedly と同じく、一覧は「All・フォルダ・フィード」で、未読だけにするかは、その一覧の状態にする。読むのは未読からなので、既定は未読だけにする。
- **畳んでいるフォルダは 1 つの配列**：フォルダごとの項目にすると、同時の変更は消えないが、フォルダを消すたびに項目を消す仕事が増える。畳む・開くは、2 台で同時に変えることが少なく、消えても押し直せば済む。値の上限（8KB）に収まるよう、200 個までにする。
- **既定と同じ値を預けない**：預けると、あとで既定を変えても、古い既定が全員に残る。sendo の書き込みと項目の数も減る。
- **localStorage の写し**：設定の正を手元の DB に移すと、DB のワーカーが開くまで（数百ミリ秒）設定が分からない。その間を既定の色で出すと、暗いテーマの人には毎回まぶしい。写しは見た目のためだけで、失っても困らない。
- **断られた変更を戻すのに `GET` を使う**：手元には、置き換える前の値を残していない。次の差分には、変わっていない項目は載らない。全体を同期し直すより、設定だけを読むほうが軽い。
- **移行待ちを DB に置く**：移行は「同期を終えたあと」にしかできないが、同期はすぐに終わるとは限らない（オフライン）。localStorage に残したままだと、同期を持つワーカー（代表のタブ）から読めない。DB に置けば、同期と同じトランザクションで、届いた設定と比べて積める。

## 検討した代替案

- **設定を localStorage に置いたまま、画面から直接 sendo に送る**：core を変えずに済むが、操作キュー（オフライン、送り直し、タブの間の調停）をもう 1 つ作ることになる。画面は sendo の API に直接触れない決まりにも反する。
- **端末の種類を、利用者が設定で選ぶ**：タブレットを `mobile` にしたい人にも合わせられるが、その選択自体は同期できず、端末ごとに選ぶ手間が増える。要ると分かってから足す。
- **種類をウィンドウの幅で決める**（画面の作りの切り替えと同じ）：作りと設定がそろうが、PC でウィンドウを狭めると設定が入れ替わる。
- **一覧ごとの設定を、1 つの項目にまとめる**：項目が 1 つで済むが、値の上限（8KB）を超え、2 台で別の一覧を変えると片方が消える。
- **同期で届いていない間は、既定で出す**（移行待ちを使わない）：単純だが、版を上げた直後にオフラインだと、設定がすべて既定に戻って見える。

## 見直す条件

- タブレットで `mobile` の設定を使いたい、種類を自分で選びたい、という声が出たとき。
- もう一方の種類の設定を写す機能を作るとき（両方の種類が手元にあるので、reader だけで作れる）。
- ほかのクライアントでやめた購読の、一覧の設定が上限に効いてきたとき（同期を終えたときに、ないフィードの項目を探して消す）。
- 頻繁に変わる値（スライダーなど）を設定に足すとき（落ち着いてから送る仕組みが要る）。
