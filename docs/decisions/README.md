# 決定の一覧

sendo-reader で決めたことを、テーマごとに1ファイルで置く。各ファイルには今の決定だけを書き、経緯は git の履歴で追う。残し方は [documentation.md](documentation.md) を参照。

サーバーとの約束ごと（認証、差分同期など）は、sendo の決定が正。[sendo の決定の一覧](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/README.md)も読む。

| テーマ | 状態 | 概要 |
|---|---|---|
| [決定の残し方](documentation.md) | 提案中 | sendo と同じ。テーマごとに1ファイルを書き換え、履歴は git が持つ |
| [UI とツール](ui.md) | 提案中 | Svelte 5 ＋ Vite の SPA（SvelteKit・Void は使わない）。現在の UI は Web の PWA で、reader のコンテナが配る。手元では Vite の dev サーバーが sendo の `pnpm dev` に中継する。ネイティブ版は配布時に Capacitor で包む。lint と整形は Biome。機能はごちゃごちゃさせず、画面に常に出す操作を絞る。読む画面（記事の一覧、記事）は没入感を優先し、行の基本の操作はスワイプに置いてよく、長押しのメニューは持たない。ほかの画面は分かりやすさを優先し、操作を見えるところに出す |
| [ワークスペース](workspaces.md) | 提案中 | All と複数選択をタブごとに保持し、一覧・検索・購読管理・一括既読を同じ範囲に揃える |
| [ローカルファースト](local-first.md) | 提案中 | 画面は手元の SQLite（公式の Wasm ＋ opfs-sahpool）だけを読み書きし、sendo の差分同期と削除記録に従う。sendo の通知（WebSocket）を受けたらすぐ同期し、定期同期も続ける。本文は記事ごとに取得して手元に置き、未読の記事の全文は同期のあとに、開いている一覧の読んでいる位置のすぐ下から 1 件ずつ選び直して先に取る（フィード本文は全文が取れないときだけ）。手元に置く本文の量は、端末ごとに選ぶ上限（既定 200MB）までにする。どのタブでも使える。ログインは sendo のセッション（HttpOnly のクッキー）で、CSP を厳しく保つ |
| [画像](images.md) | 提案中 | サムネイル、フィードのアイコン、本文の画像は sendo の中継を通す。URL は受け取ったまま使い、Service Worker でキャッシュして（100MB・30 日まで）、ログアウトで消す。ない・失敗した画像は出さない |
| [設定の同期](settings.md) | 提案中 | 表示の設定を sendo に預け、端末の種類（スマホは `mobile`、ほかは `desktop`）ごとに引き継ぐ。項目ごとに手元の DB に置いて操作キューで送り、既定と同じ値は預けない。端末そのものに合わせる設定（本文を置く量の上限）は預けない。「未読」は一覧の絞り込みの状態で、別の画面にはしない。前の localStorage の設定は、同期してから sendo にない項目だけを送る |
| [アカウントの画面](account.md) | 提案中 | 設定の画面で REST API 用と MCP 用のアクセストークン、OAuth の許可を管理し、OAuth の許可の画面を置く。どちらもネットワークが要る画面で、発行したトークンは一度だけ出して保存しない。許可は毎回、利用者が押して決める |
| [速さの予算](performance.md) | 提案中 | 画面のスレッドの JS は gzip 後 100KB 以下、ワーカーは JS と wasm で 550KB 以下。キャッシュ済みの起動から記事まで 1 秒、操作の反応は 100ms |
| [記事の翻訳](translation.md) | 提案中 | sendo が訳した記事に、元の言語と翻訳の状態を角丸の枠のラベル（`[EN] [Translated]`。言語の枠だけ色付き）で出し、一覧は訳したタイトル、記事は訳文を先に出して原文に切り替えられる（切り替えは履歴の項目に持つ）。訳せなかった記事には、sendo が配る理由（安全策で断られたなど）を記事の画面に文で出す。記事の画面には、訳したモデルと思考量の枠（`[Haiku 5.5] [low]` など）も足す。訳文のない記事は記事の画面の Translate で、訳文のある記事は More actions の Retranslate (High quality)（品質優先の段階）で、その場で頼む（sendo に届かないとできない操作）。訳した本文は訳した時刻と一緒に手元に置き、開いたときと、未読の記事を先に取るときは、全文の代わりに取る |
| [記事の中の X の投稿](embeds.md) | 提案中 | sendo が印を付けた X の引用を、表示範囲に入ったら、別のホスト名で配る隔離フレームの中の公式ウィジェットで出す。reader の CSP は `frame-src` を 1 つ足すだけ。隔離フレームのオリジンはコンテナの実行時の設定で、未設定なら出ない。失敗・オフライン・設定で切ったときは元の引用のまま。投稿の高さを幅と一緒に覚えて、読書位置を保つ |
| [コンテナ版](container.md) | 提案中 | sendo と並べて、コンテナだけで配る（`ghcr.io/sendo-feed/sendo-reader`）。Cloudflare では動かさない。外からは reader のオリジン 1 つに見せ（X の投稿の隔離フレームのホスト名を除く）、sendo の `PUBLIC_URL` と `READER_URL` をそのオリジンにする。sendo のパスは許す一覧で中継し、WebSocket も含めて書き換えない。サーバーは Node（Hono）。全文取得は事前の機能確認をせず、翻訳は記事ごとの状態、Discord は連携状態で表示と操作を決める |
