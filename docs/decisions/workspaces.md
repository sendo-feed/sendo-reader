# ワークスペース

- 状態：提案中
- 関連：[UI とツール](ui.md)、[ローカルファースト](local-first.md)、[通知](notifications.md)、[プッシュの受信と、押したとき](push-receive.md)、Sendo の[ワークスペース](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/workspaces.md)

## 決定

1. **表示は「すべて」か、選んだワークスペースの集合にする。** 新しいタブは、そのアカウントが最後に選んだ範囲で始まる（2）。覚えた範囲がないか読めない、最後の選択が All か0件選択だった、覚えたワークスペースが手元の一覧に1つもない場合は All で始まる。デフォルトもほかのワークスペースと同じように選べる。集合を選んだときはどれか1つに属するものを出し、0件選択は空の表示にする。All には未割り当てと購読のない項目も含める。サイドバーの All の上で選択中の名前と範囲を確認でき、切替メニューから複数選択、単独表示、All を選べる。
2. **選択はタブごとに覚え、最後の選択を新しいタブの初めの値にする。** アカウントを区別して `sessionStorage` に置き、再読み込み、オフライン起動、戻る・進むで適用する。URL と履歴の項目には選択を書かない。ブラウザがタブを複製する場合は、複製時の選択を引き継ぐ。選択先が手元の一覧から消えたら表示から外し、すべて消えたら空の表示にする。保存済みの ID は利用者が選択を変えるまで保持し、削除が拒否されて項目が戻ったときは元の選択で表示する。All もタブの選択として置き、選択がないのと区別する。タブの `sessionStorage` に保存した選択が読めない場合や、`sessionStorage` そのものを使えない場合は、写しを見ずに空の表示にして、利用者が範囲を選べるようにする。

   - 利用者が選択を変えたら、アカウントを区別して `localStorage` にも「最後の選択」として写す。写すのはワークスペースの ID だけで、名前は持たない。All と0件選択では写さず、前の写しを消す。写しは、最後に選択を変えたタブの選択で上書きする。
   - `sessionStorage` に選択がないタブ（新しいタブ、ホーム画面のアプリの開き直し、通知が開いた新しい窓、ブックマークレットで開いたタブ、reader の中のリンクを新しいタブで開いたとき）は、写しを初めの値にする。写しがないか読めなければ All で始める。写しは `localStorage` の置き場ごとなので、iPhone と iPad のホーム画面のアプリと Safari の間では引き継がない。
   - 引き継いだ選択は、「照らす前」の印と一緒に、すぐにそのタブの `sessionStorage` に置く。照らす前に読み込み直したら、写しではなくそこから続ける。置けなかったときは、読み込み直したときに写しから始め直す。
   - 手元の同期のカーソルが差分の全ページを揃えた状態になったら（前に揃えた一覧が手元にあれば、起動してすぐ）、そのときの手元のワークスペースの一覧と照らし、印を外す。手元に1つもなければ All にし、一部だけあれば ID を保ったまま、あるものだけを出す。照らしたあとの同期で消えたら、ほかの選択と同じく表示から外し、すべて消えたら空の表示にする。照らして All にしても、写しは変えない。
   - 照らすまでは、範囲が決まる前と同じく、引き継いだ範囲で確認できた項目だけを出す（3）。開いている詳細や URL で開いた詳細を範囲の外として外すかは、照らし終えてから決める。照らす前に利用者が選択を変えたら、その選択を使い、照らすのはやめる。
   - 開いたあとはタブごとに独立する。ほかのタブで選択を変えても、開いているタブは変わらない。
   - 写しは、ログアウトとユーザーの切り替えで、画面が手元の DB を消した知らせを受けたときに、すべてのアカウントの分を消す（[ローカルファースト](local-first.md)の「ログアウトで消す」）。知らせを受けるタブがないとき（受ける前にすべてのタブが閉じた、版の違うタブしか開いていない）は残る。
3. **各画面で同じ範囲を使う。** 一覧、検索、最近読んだ記事、サイドバー、未読数、タブタイトル、購読管理を同じ範囲で絞る。アプリのバッジと通知は例外にする。タブではなくアプリと端末に出るので、タブごとの範囲に従えない。範囲によらず、手元のすべての未読の数と、すべてのベルの通知を出す（[通知](notifications.md)の 5、[プッシュの受信と、押したとき](push-receive.md)の 2）。言葉だけのベルも、範囲によらずすべての購読の記事に当たる。ベルの一覧は範囲で絞り、範囲の外の購読のベルは、名前も数も出さずにあることだけを知らせる（[通知](notifications.md)の 7）。その引き換えに、画面を共有している間も、通知には範囲の外のフィード名と記事のタイトルが出る。記事は現在の有効な購読に従い、フォルダは対象内の購読があるものを出す。選択範囲が決まる前や、購読と所属先の照合が済む前は、対象だと確認できた項目だけを表示する。範囲を切り替えたら前の範囲で読み出した表示を取り除き、古い読み出しの結果を捨てる。開いている詳細、URL を直接開いたとき、履歴から戻ったときも照合し、外れたフィード・フォルダ・記事は名前や内容を表示せず、選択中の All に戻す。利用者が対象外の名前を見るには、切替メニュー、購読の所属先の選択、ワークスペースの管理のいずれかを明示的に開く。初版の切り替えには専用の固定モードを設けない。
4. **Saved は範囲を適用してから URL でまとめる。** 選択中のワークスペースでは、その範囲の有効な購読から来たスター記事を出す。購読解除後のスター記事と購読外から保存したページは All で出す。同じ URL の場合も、選択範囲に含まれるスター記事のタイトル・サムネイル・操作だけを使う。All では Saved の従来のまとめ方に従う。
5. **購読管理でアカウントのデフォルトと各購読の所属を管理する。** 一覧でデフォルトの1件に印を付け、別のワークスペースをデフォルトにできる。空のデフォルトを削除したい場合は、先に別のワークスペースへ切り替えるよう案内する。有効な購読が残るワークスペースは、先に購読の移動か解除が必要と知らせる。管理から名前を変えたり、各購読をフォルダを保ったまま1件ずつ移したりできる。全購読の情報を含む OPML の書き出しは All で使える。

   購読管理とブックマークレットから URL を指定して購読するときは、同じ追加画面を使う。All・複数選択・0件選択・単独表示のどの状態でも「デフォルトを使う」を初期値とし、別のワークスペースを明示的に選べる。手元のデフォルトが閲覧範囲外なら、そのことを知らせ、選択を開けば名前を確認できる。購読の応答で実際の所属を確認し、閲覧範囲外に入った場合も知らせる。追加後も閲覧範囲を保つ。選んだ所属先が消えたときは選び直せるようにし、Sendo の応答で消えたと分かった場合はその項目を候補から外して同期する。

   所属先の省略に対応していない Sendo には、従来どおり明示した ID を送る。閲覧で1つだけ選んでいればそのワークスペースを初期値とし、All・複数選択・0件選択では追加先を選ぶ。ワークスペース対応を確認できなければ対応した Sendo との同期、有効な項目が0件ならワークスペースの作成を案内する。
6. **同期と書き込みは core で扱う。** [Sendo のワークスペースの決定](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/workspaces.md)に従って差分を取り、ワークスペースと有効な購読の ID・所属を手元に置く。古いカーソルのまま更新できる。所属先の行が別ページにある場合は揃ったあとに表示し、購読の移動やワークスペースの削除から記事を消す処理は行わない。対応前の Sendo でも All の閲覧や既存購読の操作を続けられる。選択範囲を保存済みのタブは、所属を確認できる範囲で表示を続ける。

   ワークスペースの作成、改名、削除、デフォルトへの切り替え、購読の移動は、操作に対応した Sendo で利用でき、手元に反映したうえで操作キューに積む。差分の全ページが揃うまで、最後に確定したデフォルトの印を使う。切り替えや削除を拒否されたときは、その操作を外し、残りの未送信操作を同期結果に重ね直して理由を案内する。フィードの追加で所属先を省略できるかは、接続先の同期応答で新規購読への対応を確認して判断する。ワークスペースの一覧やデフォルトの印が届くこととは独立に判定する。
7. **一括既読は操作時の表示範囲で固定する。** 絞り込んだ一覧では、その一覧に入る有効な購読の ID と完了した記事の同期カーソルを、押した時点で記録する。再送でも同じ購読 ID とカーソルを渡す。記事の位置・経過時間などでさらに対象を限定する操作は、既存の個別記事 ID 指定を使う。同期の境界が揃っていない場合や送信を拒まれた場合も、対象外へ広げず、表示を同期結果に戻す。表示範囲が「すべて」の場合は従来の一括既読を使う。

## 理由

- 普段は複数のワークスペースを読め、画面を共有するときは一般のフィードだけに絞り込める。タブごとの切り替えなら、別の機器やタブの読書を中断しないで済む。
- タブの `sessionStorage` だけに置くと、ホーム画面のアプリは閉じたり OS に止められたりするたびに選択を失い、次の起動が All に戻る。最後の選択を新しいタブの初めの値にすれば、開き直しても同じ範囲で読める。開いたあとはタブごとに独立するので、ほかのタブの切り替えで共有中のタブの範囲は変わらない。
- 新しいタブは、最後に選択を変えたタブの範囲で始まるので、画面を共有しているタブより広い範囲で始まることがある。それでも All より広くはならないので、新しいタブを All で始めるより狭いか同じで済む。reader の中のリンクを新しいタブで開いたときも、元のタブではなく写しの範囲で始まり、元のタブと範囲が違えば記事を開かずに一覧に戻ることがある。元のタブの範囲を渡すには URL か履歴に選択を書くことになり、共有した URL で範囲が分かってしまうので、これを許す。
- 引き継いだ選択をすぐタブに置くのは、照らす前に読み込み直したとき、その間にほかのタブが変えた写しで範囲が広がらないようにするため。範囲の外かを照らし終えてから決めるのは、All に戻る選択で詳細を外すと、開けた記事を閉じるため。
- 写しは ID だけで、アカウントで区別するので、ログアウトの知らせを受けられずに残っても、ほかの人に名前は出ない。
- 照らすのは手元の一覧が揃ったときで、このタブの同期を待たない。待つと、オフラインや sendo に届かないときに、確認できた項目しか出ない状態が続く。
- 覚えたワークスペースが残っていないときや0件選択を引き継いで空の表示で始めると、起動した画面に何も出ず、壊れたように見える。
- 一覧のほかに検索や履歴を絞ると、通常のページ移動や再読み込みで範囲を維持できる。
- アカウントで選んだデフォルトを使えば、普段の追加で所属先を選ぶ手間が減る。必要なときは閲覧範囲を保ったまま別の追加先を選べる。
- 購読の ID を押したときに記録すると、オフラインの間に所属が変わっても一括既読の対象が広がらない。

## 検討した代替案

- ワークスペースを常に1つ表示する。普段まとめて読む用途に合わない。
- 選択を端末間で同期する。別のタブや端末からの操作で共有中の範囲が広がる。
- 新しいタブは常に All で始める。ホーム画面のアプリでは開き直すたびに範囲が広がり、選び直す手間がかかる。
- ホーム画面のアプリのときだけ引き継ぐ。ブラウザの新しいタブ、通知が開いた新しい窓、ブックマークレットでは All に戻り、場合分けが増える割に救える場面が少ない。
- 開いているタブの選択も、ほかのタブの切り替えに合わせて変える。共有中のタブの範囲が、ほかのタブの操作で広がる。
- 専用の共有モードを設ける。初版は閲覧範囲の切替までに絞る。

## 見直す条件

- 切替メニューを開いたときも選択外の名前を伏せたいと分かったとき。
- 購読の整理で複数件の移動が繰り返し必要になったとき。
- 新しいタブが前の範囲で始まるために、範囲の外の記事を開けない場面が多いと分かったとき。
