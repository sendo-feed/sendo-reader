# 記事の中の X の投稿

- 状態：提案中
- 関連：[ローカルファースト](local-first.md)（「ページの守り」）、[コンテナ版](container.md)（2・4・5）、[UI とツール](ui.md)（1・5・8）、[設定の同期](settings.md)、[画像](images.md)、sendo の[記事の本文](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/content.md)

記事の本文にある X の投稿の引用（公式の埋め込みコード）を、X の公式ウィジェットで読めるようにする。X のスクリプトは、reader のオリジンでは動かさず、別のホスト名で配る隔離フレーム（iframe）の中で動かす。投稿の見分け方（`blockquote` に付ける `data-x-post` の印）は、sendo の[記事の本文](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/content.md)が正で、ここには書き写さない。

## 決定

1. **何を出すか**：sendo が `data-x-post="<数字>"` を付けた `blockquote` を、X の投稿として出す。reader は属性の値（投稿の ID）だけを見て、引用の中の文字やリンクから投稿を照合しない。値が 1〜20 桁の数字でなければ、印がないものとして扱う。
   - 隔離フレームのオリジンが設定してあり（3）、読者の設定（[設定の同期](settings.md)）が「読み込む」（既定）なら、引用が表示範囲に入ったときに、公式ウィジェットを自動で読み込む
   - 読み込みが終わるまで、失敗したとき、オフラインのとき、設定が切ってあるときは、元の引用を出す。ウィジェットが出たら、元の引用を隠して置き換える。置き換わるときに、その下の本文が 1 回動くのは受け入れる
   - 投稿を X で開くリンクは、ウィジェットの有無によらず常に出す
   - 印は本文を開くたびに読む。印のない本文（sendo が印を付ける前に保存したもの）には、さかのぼって効かせない
2. **隔離の境界**：reader のオリジンでは、X のスクリプトを動かさない。
   - reader の CSP に足すのは `frame-src <隔離フレームのオリジン>` だけ（[ローカルファースト](local-first.md)の「ページの守り」）。`script-src`、`connect-src`、`img-src`、`style-src`、Trusted Types は変えない。未設定なら、`frame-src` も足さない
   - 隔離フレームに渡すのは、投稿の ID とテーマだけ。本文の HTML の文字列は、画面にも iframe にも渡さない。`srcdoc` は使わない
   - 投稿 1 つにつき、iframe を 1 つ出す。属性は次のとおり。`src` は、reader が表示範囲に入ったと判定してから付ける（`loading="lazy"` は付けない）

     ```html
     <iframe src="<隔離フレームのオリジン>/#id=<ID>&theme=<light か dark>"
       sandbox="allow-scripts allow-same-origin allow-popups allow-popups-to-escape-sandbox"
       allow="fullscreen" referrerpolicy="no-referrer" title="X の投稿"></iframe>
     ```

   - 隔離フレームのページは、外部の `embed.js` と空の入れ物だけ。`embed.js` は `https://platform.twitter.com/widgets.js` を読み込み、`twttr.widgets.createTweet(id, 入れ物, { dnt: true, lang: "ja", conversation: "none", theme })` を呼ぶ。`color-scheme` は、ハッシュの `theme` から `document.documentElement.style.colorScheme` で付け、reader のテーマとそろえる
   - 隔離フレームのページの応答のヘッダー：`Content-Security-Policy: default-src 'none'; script-src 'self' https://platform.twitter.com; frame-src https://platform.twitter.com; base-uri 'none'; form-action 'none'`、`Referrer-Policy: no-referrer`、`X-Content-Type-Options: nosniff`、`Permissions-Policy`（reader と同じ）。ページに `<meta name="twitter:widgets:csp" content="on">` を置く。Trusted Types は入れない（`widgets.js` が止まる）。許すのは `platform.twitter.com` のホストだけで、パスまでは絞らない
   - やり取り：枠の `load` で、reader が `iframe.contentWindow.postMessage({ type: "sendo:x-post:hello" }, <隔離フレームのオリジン>)` を送る。隔離フレームは `event.source === window.parent` を確かめ、`event.origin` を送り先として覚える。隔離フレームが送るのは、覚えたオリジンに、次の 2 種類だけ
     - `{ type: "sendo:x-post:rendered", height }`：`createTweet` の Promise が要素で解決したあと。`height` は、余白を含めた入れ物の高さ（整数。枠の高さによらない値）。解決の前には、高さを送らない。解決のあとは、高さが変わるたびに、同じ形でもう一度送る（枠の幅が変わると、ウィジェットの高さも変わる）
     - `{ type: "sendo:x-post:failed" }`：`widgets.js` の `onerror`、`twttr` がない、Promise が `undefined` で解決した、Promise が reject した
   - reader は、`event.origin` が隔離フレームのオリジンで、`event.source` がその iframe の `contentWindow` のメッセージだけを受ける。`height` は 1〜4000 の整数だけを受け、`style:` で付ける。2 回目からの `rendered` は、枠の高さを付け直すだけにする
3. **隔離フレームの配り方と設定**：reader のコンテナが配る（[コンテナ版](container.md)の 2・4・5）。
   - 設定は、実行時の環境変数 `X_EMBED_ORIGIN`（隔離フレームのオリジン）の 1 つだけ。未設定なら、この機能は出ない（画面は X へ通信しない）。イメージは 1 つのままで、使う人は作り直さない
   - 隔離フレームのオリジンは、reader とホスト名が違う `https` のオリジンにする。ホスト名が同じでポートだけが違うオリジンは使わない（セッションのクッキーは、ポートで分かれない）。reader と別のサイト（登録できるドメインが違う）に置くのを勧める。同じサイトに置くと、ブラウザーが reader と同じプロセスで動かすことがあり、X のスクリプトが画面の速さに響く
   - コンテナは、起動時に値の形（`https`、パス・クエリ・ハッシュ・認証情報なし）を確かめ、合わなければ理由を出して起動しない
   - コンテナは、要求の `Host` がこのホスト名なら、隔離フレームのページ（`/` と `/embed.js`）だけを返す。sendo には中継しない。ページは画面のビルドとは別に置き、reader のホスト名では返さず、Service Worker の precache にも入れない。reader のためのパスは増えない（[コンテナ版](container.md)の 6）
   - 画面には、コンテナが起動時に `index.html` に埋めた `<meta name="sendo-x-embed-origin" content="<隔離フレームのオリジン>">` で渡す。画面はこの `<meta>` を読み、なければ未設定として扱う。reader の CSP の `frame-src` と、この値は、同じ `index.html` の応答から来る
   - 設定を変えたら、読者には、新しい版への切り替え（[UI とツール](ui.md)の 5）と同じ時点で届く。コンテナは、起動時に `sw.js` の precache の一覧のうち、`index.html` の revision を、書き換えたあとの `index.html` の中身と付ける CSP から作った値に替える。書き換える場所が見つからなければ、理由を出して起動しない。未設定なら、`index.html` も `sw.js` も、ビルドしたものから変えない
   - 隔離フレームのページには、`frame-ancestors` を付けない。ほかのサイトがこのページを iframe に入れられることは、受け入れる
4. **成功と失敗、読み込みを始める条件**
   - 成功は、最初の `rendered` を受け取ったとき。高さが 0 より大きいことは、成功の印にしない
   - 失敗は、`failed` を受け取ったとき、または、枠が表示範囲に入っている時間の合計が 10 秒になっても `rendered` が来ないとき（画面の外にいた時間は数えない）。失敗したら、iframe を外して元の引用のままにし、その記事を開いている間はやり直さない
   - 読み込みは、引用が表示範囲（ツールバーの下は数えない）に入ったときに始める。読書位置が決まる前は始めない。同時に読み込むのは 4 つまでで、待っている間に表示範囲から出たものは取り消す。読み込み中（`rendered` の前）に表示範囲から出たものも、iframe を外して元の引用に戻し、4 つの数から外す。入り直したら、最初から読み込む（10 秒も数え直す）
   - オフラインでは始めず、`online` で判定し直す。設定が「読み込まない」か、隔離フレームのオリジンが未設定なら、始めない（通信しない）。復元のために、画面の外の投稿を先に読み込むことはしない
5. **読書位置**：`history.state` の記事の位置（[UI とツール](ui.md)の 1）に、投稿ごとの `{ 幅, 高さ }` を一緒に覚える。覚えるのは、表示範囲の中で `rendered` を受け取ったときの値だけで、受けるたびに、そのときの幅と高さで覚え直す。
   - 戻るときは、覚えた幅が今の枠の幅と同じ投稿に限り、読み込む前からその高さの枠を取る（元の引用は出さない）。読み込めないとき（隔離フレームのオリジンが未設定、設定が「読み込まない」、オフライン）は、枠を取らずに元の引用を出す。位置は、今のスクロール量のままで合う。枠は表示範囲に入ってから読み込み、失敗したら元の引用に戻す。読み込みの途中で表示範囲から出たら、iframe を外して、覚えた高さの空の枠に戻す。読み込みを始める前に読み込めなくなったら、元の引用に戻す
   - 読み込めずに元の引用を出した投稿が画面より上にあると、位置は、ウィジェットとの高さの差だけずれる。これは受け入れる
   - 初めて出す投稿が、画面より上で元の引用から置き換わるときは、ブラウザーのスクロール量の補正に任せる
   - 位置を、本文の要素を基準にして覚えることはしない
6. **スワイプとキーボード**
   - ウィジェットの上に、透明な覆いを置く。覆いの上からの横のスワイプと縦のスクロールは、reader が受ける。覆いを 1 回押すと外れ、ウィジェットの中を操作できる。ウィジェットが表示範囲から出たら、覆いを戻す
   - reader の `window` の `blur` で、`document.activeElement` がウィジェットの iframe なら、本文に `focus({ preventScroll: true })` する。押したあとも `j` ／ `k` ／ `Esc` が効く。キーボードだけでウィジェットの中を操作することは、できない
7. **X に伝わること**
   - 表示範囲に入った投稿ごとに、読者の IP、開いた時刻、投稿の ID、隔離フレームのホスト名が X に伝わる。`dnt: true` を付けるが、計測の通信（`syndication.x.com/i/jot/embeds`）は減らない（`dnt=1` が付くだけ）
   - 通信の量は、投稿 1 つで約 450KB。動画付きは、再生を押す前から約 1.8MB。読み込みの途中で表示範囲から出て、入り直した投稿は、読み込み直すので、もう一度伝わる
   - 隔離フレームの URL は、ハッシュまで丸ごと X に渡る。ハッシュには ID とテーマだけを入れ、reader のオリジンは入れない（`Referer` も付かない）。ただし、隔離フレームの中のスクリプトは、親のオリジンを知りうる（挨拶の `event.origin` など）。隔離フレームのホスト名を reader のドメインの下に置けば、そのドメインも X に伝わる
   - 隔離フレームのオリジンにも X の文書にも、クッキーや保存領域は置かれない。X が付けるのは、ボット対策のクッキー（`__cf_bm`。最上位のサイトごとに分かれる）だけ

## 理由

- **隔離フレームで動かす**：X のスクリプトを reader のオリジンで動かすと、セッションで API を使え、手元のデータも読める。CSP の `script-src` と `connect-src` を X に開き、Trusted Types も外すことになる（`widgets.js` は Trusted Types の下で止まる）。別のホスト名の文書に閉じ込めれば、reader の守りは `frame-src` を 1 つ足すだけで保てる。
- **sendo が投稿を特定する**：引用の出典の文字列から投稿を照合すると、書き方のゆれ（空の文、装飾、改行、補足のリンク）に弱い。属性の ID だけを見れば、reader は文字列を解釈しない。`createTweet` は ID だけを受け取り、ホスト（`x.com` ／ `twitter.com`）は関係しない。
- **自動で読み込み、元の引用から置き換える**：今の引用は、記事の書き方によってはほとんど何も読めない（文が空、リンクだけ）。押すまで読み込まない形では、毎回 1 手間かかる。表示範囲に入った分だけを読み込めば、X に伝わるのは読者が見た投稿だけになる。元の引用を残すと、同じ投稿が 2 回並ぶ。
- **成功を `rendered` で決め、表示範囲の中の時間で打ち切る**：消えたアカウントの投稿は、Promise が解決しないまま、高さ 76px の「見つかりません」を出すので、高さでは決められない。Chromium は画面の外の枠を解決させないので、画面の外の時間を数えると、成功するはずの枠を失敗にし、読み込み中の枠を画面の外に残すと、4 つを占め続けて、あとの投稿が読み込まれない。画面の中の成功は、10 個を同時に読み込んでも 1.5 秒に収まり、10 秒はその 6 倍以上ある。
- **高さを幅と一緒に覚える**：同じブラウザー、同じ幅、同じオプションで、画面の中で描画した高さは毎回同じで、Promise の解決と同時に 1 段階で決まる。隔離フレームが解決まで高さを送らなければ、覚えた高さの枠から読み込み直しても、本文は動かない。幅が違うと高さも違い、画面の外では高さが変わる（WebKit）ので、同じ幅と画面の中に限る。
- **実行時の設定にし、`index.html` に埋めて `sw.js` で届ける**：隔離フレームには、reader と別のホスト名が要り、それは使う人ごとに違う。ビルド時の設定では、上流のイメージを使う人が作り直すことになる。CSP と設定の値を同じ `index.html` の応答から取れば、食い違わない。`sw.js` の版の印を替えれば、今ある「新しい版への切り替え」で、Service Worker が `index.html` を取り直す。
- **`frame-ancestors` を付けない**：付けるには、reader のオリジンをコンテナに教える設定がもう 1 つ要る。ページが出すのは ID で指した公開の投稿だけで、クッキーも reader のデータも持たず、X との通信は訪問者のブラウザーから直接出る。
- **覆いとフォーカスを戻すこと**：iframe の中のタッチとキーの入力は、親に届かない。覆いがないと、ウィジェットの上から記事のスワイプが始まらず、一度押すと `j` ／ `k` ／ `Esc` が効かなくなる。

## 検討した代替案

- **reader のオリジンで `widgets.js` を動かす**：作りは小さいが、上の理由で reader の CSP と Trusted Types を大きく緩めることになる。
- **読者が押してから読み込む**：X に伝わるのは押した投稿だけになるが、読むたびに 1 手間かかる。伝えたくない読者は、設定で切れる。
- **sendo が X から投稿の中身を取り、本文に入れる**：読者から X へ通信しなくなるが、中身を取るには、有料の API か、公式でない取得口に頼ることになる。動画も出せない。
- **位置を本文の要素で覚える**：高さを覚えなくてよいが、要素の道の付け方と、引用・画像・改行ごとの戻し方が要り、作りが大きい。
- **ビルド時の設定にする**：コンテナの書き換えが要らないが、使う人がイメージを作り直すことになる（[コンテナ版](container.md)の 1）。
- **設定のファイル（`/config.json`）を返す**：`index.html` を書き換えずに済むが、CSP は古いのに設定は新しい、という食い違いが起き、reader のためのパスも増える。
- **効くのは次の版から、と決める**：`sw.js` を書き換えずに済むが、使う人が設定しても、上流が次の版を出すまで効かない。
- **`index.html` を precache から外す**：設定がすぐ効くが、オフラインで起動できなくなる。
- **Service Worker を自前で書く**：届き方を細かく決められるが、作りが大きく変わる。
- **`frame-ancestors` を付ける**：ほかのサイトに使われなくなるが、設定が 2 つになる。困ったら、あとから足せる。
- **上流が隔離フレームを 1 か所で配る**：使う人の設定が要らないが、すべての読者の IP と開いた時刻が上流にも集まり、上流が止まると全員の X の投稿が出なくなる。

## 見直す条件

- X がウィジェットの作り、置き場、通信先を変えたとき（隔離フレームの CSP と、成功・失敗の決め方を確かめ直す）。
- Workbox の出力の形が変わり、`sw.js` を書き換えられなくなったとき。
- Service Worker が返した `index.html` の CSP が、取り直した応答のヘッダーのものにならないと分かったとき。
- iOS の Safari や Firefox で、位置がずれる、出ない、と分かったとき（確かめたのは Chromium と、デスクトップの WebKit）。
- 通信の量や、X に伝わることが困ると分かったとき。
- 隔離フレームのページが、ほかのサイトに使われて困ると分かったとき（`frame-ancestors` を足す）。
