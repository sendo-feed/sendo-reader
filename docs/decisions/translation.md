# 記事の翻訳

- 状態：提案中
- 関連：[ローカルファースト](local-first.md)、[UI とツール](ui.md)、[コンテナ版](container.md)、sendo の[記事の翻訳](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/translation.md)・[差分同期](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/sync.md)

sendo が日本語に訳した記事を、reader でどう見せ、どう訳してもらうか。何をいつ訳すか、訳文の状態、配り方は、sendo の[記事の翻訳](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/translation.md)と[差分同期](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/sync.md)の 10 が正で、ここには書き写さない。

この決定で「訳文がある」は、記事に訳した時刻が届いていること（訳し直しの最中も含む）を指す。

## 決定

### 見せ方

1. **一覧の行と記事の画面に、元の言語と翻訳の状態を、それぞれ角丸の枠で囲んで並べる**（`[EN] [Translated]`）。枠を並べたまとまりを「ラベル」と呼ぶ（記事の画面では、下で足すモデルと思考量の枠も含む）。状態は `Queued`（バッチを待っている）、`Translating`（その場の翻訳か訳し直しの最中）、`Translated`（訳文がある）、`Untranslated`（訳文がない）。
   - 言語は、sendo が配る ISO 639-1 を大文字にしたもの。状態は、差分同期で届いたものを手元の DB に置いて出す
   - 翻訳の項目が届かない記事（日本語の記事、Discord の投稿、sendo がまだ訳すかどうかを決めていない記事と決めずに終えた記事、API キーのない sendo、翻訳に対応する前の sendo）には、ラベルを出さない
   - 言語が判定できなかった記事（`und`）は、言語の枠を出さず、状態の枠だけを出す（`Untranslated`、`Translating`、`Translated`。`und` の記事は `queued` にならない。sendo の[記事の翻訳](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/translation.md)の 1）
   - 言語の枠だけ、どの言語も同じ 1 色で塗る（色は `apps/web/src/app.css` の変数）。状態の枠と、記事の画面だけに足すモデルと思考量の枠は、線だけにして色で分けない。一覧の行ではメタ（フィード名、時刻）の並びに、記事の画面では見出しの下のメタの並びに置く
   - 記事の画面では、出している状態が `Translated` のとき、状態の枠のあとに、訳したときのモデルと思考量を、それぞれ 1 つの枠で足す（`[EN] [Translated] [Haiku 5.5] [low]`）。sendo が配る条件から出す（訳文の代表の部分を作った条件で、同じ元記事から写した訳文は、写した元の条件。sendo の[記事の翻訳](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/translation.md)の 18）。一覧の行には足さない
     - モデルは、ID 全体が `claude-<系列>-<主版>`、`claude-<系列>-<主版>-<副版>`、またはそのどちらかのあとに `-<日付>` が付いた形なら、系列の名前と版にする。系列は小文字の `sonnet` ／ `haiku` ／ `opus`、主版と副版は 1〜2 桁の数字、日付は 8 桁の数字。日付は出さない。副版は 0 でも出す。例：`claude-sonnet-5-5` → `Sonnet 5.5`、`claude-sonnet-5` → `Sonnet 5`、`claude-haiku-4-5-20251001` → `Haiku 4.5`、`claude-sonnet-4-20250514` → `Sonnet 4`、`claude-sonnet-4-0` → `Sonnet 4.0`
     - ほかの ID は、届いたまま出す（大文字を含むもの、`claude-sonnet-latest`、`claude-3-5-sonnet-20241022`、日付のあとに続きがあるもの、版が 3 つ以上のものなど）
     - 思考量は、届いた値（sendo の[記事の翻訳](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/translation.md)の 9）をそのまま出し、知らない値も届いたまま出す
     - 文字でない値と空の文字は、届かないものとする（翻訳のほかの項目は使う）。思考量が届かなければモデルの枠だけを足し、モデルが届かなければどちらの枠も足さない
     - 条件を配る前の sendo か、条件に対応する前の reader の版で受けて手元に置いた記事には、モデルがない。その記事が差分同期で届き直す（受信箱の行の既読やスターが変わった、翻訳が変わった）までは足さない。最初から同期し直させず、それまで足さないまま受け入れる
     - `Translating` の間（6 の頼んだ印のある間と、訳し直しの最中。もとの訳文を出していても）は足さない
     - 足す条件は、ラベルの状態と同じく、届いた翻訳（手元の DB）から出す。開いている間に訳文が替わり、出している本文を替えないとき（3）も、条件は替わる
   - 記事の画面では、出している状態が `untranslated` で（6 の頼んだ印のある間は `Translating` なので出さない）、sendo が訳せなかった理由を配っている記事に、ラベルの下に理由の文を出す（sendo の[記事の翻訳](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/translation.md)の 17）。手元の DB に置いた理由から出すので、どの端末から開いても、読み込み直しても出る。一覧の行には出さない。文は理由ごとに分ける
     - 拒否・バッチ：安全策で翻訳を断られたことと、Translate で頼み直すと通ることがあること。別のモデルで試すとは言い切らない（その場の翻訳で、断られたときに別のモデルで試すかは、sendo の設定のモデルによる。sendo の[記事の翻訳](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/translation.md)の 9）
     - 拒否・その場の翻訳：安全策で翻訳を断られたことと、頼み直しても同じ結果になる見込みが高いこと
     - そのほかの失敗：「訳せませんでした。Translate でもう一度頼めます。」
     - 拒否の種類は、知っているもの（`cyber` →「サイバーセキュリティ」など）だけを日本語にして文に添え、知らないものと空のものは添えない
     - 種類やどこで起きたかに知らない値が届いたら（版の違う sendo）、そのほかの失敗の文を出す
     - Translate は、理由があっても今のとおり出す（押せる）
2. **一覧の行は、訳したタイトルがあれば、それを出す。**
3. **記事の画面は、訳文があれば訳文を先に出し、原文に切り替えられる。**
   - 訳文は、訳したタイトルと、訳した本文（8）。sendo が本文を訳さなかった記事では、原文の本文を出す。訳した本文を取っている間と、手元にないとき（オフライン）は、訳した要約を出す
   - 切り替えは、More actions の Show original text ／ Show translation に置く。どちらを出しているかは、履歴の項目（`history.state`）に、記事の位置と一緒に持つ。読み込み直しても、戻る・進むでも、同じ本文の同じ位置に戻る（[UI とツール](ui.md)の 1）。URL と設定には入れず、記事を新しく開くと訳文から出す
   - 訳文を出している間は、全文とフィード本文の切り替え（Show full text ／ Show feed content）を出さない。原文に切り替えてから出す。ただし、sendo が本文を訳さなかった記事では、原文の本文を出すので、これまでどおり出す。原文の本文の出し方は、[ローカルファースト](local-first.md)の「記事の本文」のまま
   - Download は、出している方を書き出す（開いている間に訳文が届いたり替わったりしても、出しているタイトルと本文）。訳文を出していれば、訳したタイトルと訳した本文を書き出す（訳した本文が手元になければ出さない）。sendo が本文を訳さなかった記事では、訳したタイトルと全文を書き出す。原文を出していれば、これまでどおり全文を書き出す
   - 開いている間に訳文が届いたり替わったりしても（バッチが終わった、ほかの端末で訳し直した、同じ元記事のほかの記事の訳が写った・訳し直された。sendo の[記事の翻訳](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/translation.md)の 16）、出している方（訳文か原文）のタイトルと本文をまとめて替えない。替えるのは、この端末でその記事の Translate か Retranslate (High quality) を頼んだとき（6）と、訳した要約を出して訳した本文を待っているときだけ

### 訳してもらう

4. **訳文のない記事は、記事の画面の Translate で、その場で訳してもらう。** 押したときだけ頼み、開いただけでは頼まない。
   - Translate は、状態が `queued` ／ `untranslated` の記事（`und` の記事も含む）で、記事の画面のラベルのすぐ横に出す。翻訳の項目が届かない記事には出さない
   - 一覧の行には出さない（[UI とツール](ui.md)の 8）
5. **訳文のある記事は、More actions の Retranslate (High quality) で、品質優先の段階（sendo の[記事の翻訳](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/translation.md)の 9）で訳し直してもらう。** 名前にモデルを出さない（sendo の設定で変わる）。状態が `translated` で、まだ訳し直していない記事（ほかの記事から訳し直しが写って印が届いた記事も、訳し直したものとする）にだけ出す。
   - 押したら、ボタンと同じ名前の確かめの窓で、品質を優先するモデルで訳し直すことと、「訳し直した訳文は、この記事と、同じ元記事のほかの記事を読むすべての人の訳文を置き換える」と伝え、選んでから頼む（sendo は、同じ元記事のほかの記事にも訳し直しを写す。細部は sendo の[記事の翻訳](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/translation.md)の 16）
6. **頼む操作は、sendo に届かないとできない操作にする**（[ローカルファースト](local-first.md)の 1 の例外）。
   - 操作キューには積まない。オフラインのときは、Translate と Retranslate (High quality) を出したまま押せなくする。押してから応答までも、押せなくする
   - sendo が受け付けたら（202）、core のメモリーに「頼んだ」印を記事ごとに置き、すべてのタブに知らせて、同期を頼む。印のある記事は、ラベルを `Translating` にして、押せなくする。印は、202 のあとに始めた同期が成功して終わったときか、1 分たったときに外す（そこからは、届いた状態で出す）
   - その場の翻訳を頼んで `translation_exists` が返ったときは、もう訳しているか訳し終えているので、失敗の文を出さず、受け付けられたときと同じに扱う。そのほかの断られたとき（`translation_unavailable`、`retranslation_not_allowed` など）と、届かなかったときは、理由を日本語の文で出す（`apps/web/src/lib/errors.ts` で文にする）。`retranslation_not_allowed` のときは、手元の状態が古いので、同期も頼む
   - この端末で頼んだ記事は、core のメモリーに覚える。202 のあとに始めた同期が成功して終わった時点かそのあとに、その記事がその場の翻訳なら `untranslated`、訳し直しなら訳し直しの印のない `translated` だったら、訳せなかったとして失敗の文を出す（sendo は 202 を返す前に `translating` にするので、その同期のあとで見えるこれらの状態は、訳せずに戻ったもの）。訳文が届くか失敗の文を出したら（長くても 1 時間で）忘れる。その場の翻訳で `untranslated` に戻り、理由が届いている記事では、この失敗の文の代わりに 1 の理由の文を出し、同じことを 2 つ出さない（受け付けを取り消して戻ったときは、sendo が残すもとの理由の文になる）。訳し直しの失敗は、理由を見ずに今の失敗の文を出す
   - 頼んだ印と頼んだ記事は、core のメモリーにだけ置き、ログアウトとユーザーの切り替えで消す。代表のタブが替わったときも消え、そこからは届いた状態で出す
7. **キーボードの `t` で、訳文と原文を切り替える。** 訳文がなく Translate を出している記事では、Translate と同じ。操作の一覧（`?`）に足す。

### 手元に置く

8. **訳した本文は、記事ごとに取りにいき、手元に置く。**
   - `GET /api/v1/articles/{id}/translation` で取り、受け取った HTML を、原文の本文とは別の表に、訳した時刻と一緒に置く。記事を消すと一緒に消す
   - 画面に渡すときに、core で `ContentNode` の木にする（[UI とツール](ui.md)の「守る規約」。原文の本文と同じく、HTML の文字列は画面に渡さない）。木にして出すもの（文字か画像）が残らない本文は、本文を訳さなかったときと同じに扱う
   - 置くのは、取った本文の訳した時刻が、手元に置いてある訳した本文より新しいときだけにする（同じ文の中で確かめる）。遅れて返った古い本文で、新しい本文を上書きしない
   - 新しく開くときと先に取るときに使うのは、記事の訳した時刻と合う本文だけ。合わない本文は使わず、次に要るときに取り直す。開いている間の出し方は 3 に従う
   - 訳した本文のない応答（sendo が本文を訳さなかった）を受けたら、その訳した時刻での印を手元に置き、取り直さない
   - 手元に置く本文の量の上限に含め、上限を超えたときは、原文の本文と同じ順で消す
9. **訳文のある記事を開いたら、全文ではなく、訳した本文を取る。** 全文は、原文に切り替えたときに取る（[ローカルファースト](local-first.md)の「記事の本文」）。本文を訳さなかった印のある記事は、開いたときもこれまでどおり全文を取る。
10. **未読の記事を先に取るとき、訳文のある記事は、訳した本文を取る**（[ローカルファースト](local-first.md)の「記事の本文」）。
    - 手元に今の訳した時刻の訳した本文がなければ、全文があっても選ぶ。選ぶ順と件数の決まりは変えない
    - 本文を訳さなかった印のある記事は、これまでどおり全文を取る
    - 取った本文の訳した時刻が記事と合わなかった記事（取る間に訳し直した）は、その回で取れなかった記事として扱い、その回では選び直さない
    - 先に取った全文は、あとで訳文が届いても消さない（原文に切り替えたときに使う。上限の決まりで消える）
11. **訳したタイトルと本文は、手元の検索の対象にしない。** 探すのは、これまでどおり原文。

## 理由

- **言語と状態を枠に分けて並べ、言語にだけ色を付ける**：枠にすると、言語・状態・モデル・思考量の切れ目が、文字の区切り（`·`）なしで分かる（版の数字と思考量が並んでも読み違えない）。言語に色を付けるのは、一覧で外国語の記事が目立ってよいため。日本語の記事と見分けて、読むか、訳文で読むかを選ぶ手がかりになる。言語ごとに色を変えないのは、見分けたいのは外国語かどうかで、色が増えると一覧で目立ちすぎるため。[UI とツール](ui.md)の 8 が読む画面で絞るのは常に出す操作で、読む記事を選ぶ手がかりの色はそれに当たらない。言語が判定できなかった記事（`und`）は言語の枠がないので色が付かないが、状態の枠で翻訳の対象と分かれば足りる。状態とモデル・思考量は、読めば分かれば足り、色を足すと未読やスターと競うので、線だけにする。`und` の記事は、言語を出せないので、状態の枠だけを出す。`Untranslated` も出すのは、sendo がまだ訳すかどうかを決めていない記事（ラベルなし）と見分け、自動では訳されず Translate を押さないと訳されないと分かるようにするため。出さないと、待てば訳されるように見える。
- **訳せなかった理由を記事の画面に出す**：`Untranslated` だけでは、Claude の安全策に拒否されたのか、一時的な失敗が続いたのかが分からず、Translate を押す意味があるかを決められない。バッチには代わりのモデルがなく、既定では長文をその場の翻訳と別のモデル（長文の段階）で訳すので、バッチで拒否された記事は Translate で通ることがあるが、その場の翻訳でも拒否された記事は、頼み直しても同じになりやすい。バッチで拒否された記事の文で、別のモデルで試すと言い切らないのは、代わりのモデルのないモデルを通常の段階に選べ（sendo の[記事の翻訳](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/translation.md)の 9）、reader には sendo の設定が分からないため。一覧の行に出さないのは、行が混み、理由は記事を開いて Translate を押すかを決めるときにだけ要るため。拒否の種類を知っているものだけ訳し、知らない値にはそのほかの失敗の文を出すのは、sendo（Anthropic）が種類や値を増やしうるため。その場の翻訳で拒否された記事でも Translate を出したままにするのは、必ず断られるとは限らず（代わりのモデルの選び方も変わりうる）、押すかどうかは、理由を読んだ人に任せるため。
- **訳したモデルと思考量を記事の画面のラベルに出す**：同じ記事でも、どのモデルで訳したかで品質が違い、長文の段階では、量の多い訳文の費用を抑えるために、通常の段階より安いモデルと少ない思考量を既定にする（sendo の[記事の翻訳](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/translation.md)の 9）。`[Haiku 5.5] [low]` と分かれば、読む人が品質優先で訳し直すかを決められる（sendo の[記事の翻訳](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/translation.md)の 18）。版まで出すのは、同じ系列でも版で品質が違い、どの版で訳したかが分かれば、新しい版が出たときに訳し直すかも決められるため。ID のまま出さず、系列の名前と版（`Sonnet 5.5`）にするのは、短く読みやすくするため。日付を出さないのは、同じ版のスナップショットの日付は、読む人の判断に要らないため。条件を配る前に手元に置いた記事を、最初から同期し直させて埋めないのは、多くは読み終えた古い記事で、訳し直すかを決める場面が少なく、そのために全部を取り直すのは重いため。未読の記事は、開いて既読にすれば届き直す。最初から同期した端末（新しい端末など）では同じ記事にも出るので、端末によって出たり出なかったりするが、受け入れる。知らない ID を届いたまま出すのは、系列の名前と版に直せなくても、どのモデルかは伝わるため。一覧の行に出さないのは、行が混み、訳し直すかを決めるのは記事を開いたときだから。`Translating` の間に出さないのは、もとの訳文の条件が「いまそのモデルで訳している」と読まれるため。条件を出している本文ではなく届いた翻訳に合わせるのは、ラベルの状態、Translate、Retranslate (High quality) も届いた翻訳で決めているので、条件だけを本文に合わせると、訳し直しの印が届いてボタンが消えたのに、ラベルは前のモデルのまま、と食い違うため。
- **訳し直しのボタンの名前にモデルを出さない**：品質優先の段階のモデルは、sendo の設定で変わる。名前にモデルを書くと、設定を変えたときに名前と実際が合わなくなる。
- **Translate をラベルの横に置く**：訳文のない外国語の記事を開いたとき、まず要るのが Translate で、要る記事にだけ出る。ラベルの横なら、何の操作かが状態と一緒に分かる。
- **訳し直しと切り替えを More actions に置く**：訳し直しは、品質が足りないときだけのまれな操作で、費用もかかる。原文への切り替えも、訳文で読むのが既定なのでまれ。どちらも常に出す操作にしない。キーボードの `t` は、見えるところでできることの近道にする。名前を Show original text にするのは、元のサイトを開く操作と見分けるため。訳文と原文の切り替えは、何語で読むかを選ぶ操作で、原文の中のどの本文（全文、フィード本文）を出すかとは別の操作として並べる。
- **切り替えを履歴の項目に持つ**：記事の位置は本文ごとに違うので、新しい版への切り替えで読み込み直したときに訳文に戻ると、違う本文の位置に飛ぶ。設定にしないのは、原文で読むかどうかは記事ごとに決まり、ほかの記事に持ち越さないため。
- **Download は出している方を書き出す**：本文を訳さなかった記事では、画面は訳したタイトルと原文の本文を出す。書き出すのも訳したタイトルにし（本文は、原文を出しているときと同じく全文）、画面のタイトルとファイル名を合わせる。原文に切り替えなくても書き出せる。
- **開いている間に届いた訳文で替えない**：読んでいる途中で本文が入れ替わると、読んでいた場所を見失う。自分で頼んだときと、要約で本文を待っているときは、訳文を待っているので替える。
- **その場の翻訳を自動にしない**：その場の翻訳は、バッチの倍の料金がかかる。開いた記事を自動で訳すと、バッチを待てば半額で済む記事や、訳さなくてよい記事にも払う。
- **頼む操作を操作キューに積まない**：ほかの操作と違い、手元に先に反映できる結果がない（訳文は sendo が作る）。オフラインで積んでおくと、あとで送ったときには、もうバッチで訳し終えていて、要らない料金がかかりうる。頼んだ印を同期のあとで外すのは、202 より前に始まった同期が古い状態を届けて、ボタンが戻るのを防ぐため。失敗を状態の移り方ではなく同期のあとの状態で決めるのは、sendo ですぐに失敗すると、手元が `translating` を一度も見ないことがあるため。
- **受け取った HTML を置き、画面に渡すときに木にする**：どちらの時に木にしても、画面に渡るのは木だけで、守りは同じ。受け取った HTML を置けば、通すタグと属性を後から厳しくしたとき、手元に置いた本文にもすぐ効く。原文の本文と同じ作りにする。出すたびに木にする手間は小さい。
- **訳した時刻を確かめて置く**：訳し直すと、同じ記事の訳文が替わる。古い時刻の取得が遅れて返ったときに置くと、訳し直しは 1 回だけなので、古い訳文が残り続ける。手元の記事より新しい本文は置いておき、同期で時刻が届いたら使う。
- **訳した本文を先に取り、開いたときも訳した本文を取る**：訳文で読むのが既定なので、原文の全文だけを先に取っても、オフラインでは訳文で読めない。全文も同時に取ると、本文を置く量の上限を倍の速さで使う。sendo が訳文を作るのは記事を取り込んでしばらくあとなので、全文を先に取ったあとの記事も選び直す。
- **訳したタイトルと本文で探さない**：手元の検索の索引を訳文にも作ると、索引の大きさと作る手間が倍になる。まずは原文で探せれば足りる。

## 検討した代替案

- **言語と状態を 1 つの文字のラベル（`EN · Translated`）にし、色で分けない**：一覧の行は控えめになるが、版の数字と思考量が並ぶと切れ目が分かりにくく、外国語の記事が一覧で目立たない。
- **状態ごとに色を変える**：状態の違いは目立つが、一覧で未読やスターと競う。状態は読めば分かれば足りる。
- **訳文と原文の切り替えを、記事の画面の操作に常に出す**：訳文で読む間はほとんど使わず、操作が増える。
- **訳文か原文かの既定を、設定で選べるようにする**：使う人が少ないうちに設定を足すと、外しにくい。原文で読みたい人が多いと分かったら足す。
- **取ったときに木にしてから置く**：出すたびに木にする手間は省けるが、通すタグと属性を変えても、手元に置いた本文には効かず、古い決まりで作った木が残る。
- **訳した本文と全文を、両方先に取る**：オフラインで原文も読めるが、本文を置く量の上限を倍の速さで使う。
- **モデルと思考量を一覧の行にも出す**：記事を開く前に訳文の品質の見当が付くが、行が混む。訳し直すかは記事を開いてから決める。
- **系列の名前だけにする（`[Haiku] [low]`）**：ラベルは短くなるが、同じ系列の版の違い（新しい版で訳したか）が分からない。
- **モデルの ID のまま出す（`[claude-haiku-5-5] [low]`）**：正確だが長く、読みにくい。
- **出している本文を作った条件を出す**：開いている間に訳文が替わっても本文とラベルが合うが、ラベルの状態とボタンは届いた翻訳で決めるので、そちらと食い違う。
- **ボタンの名前にモデルを書く（Retranslate with Opus など）**：品質優先の段階の既定のモデルは分かるが、sendo の設定で品質優先のモデルを変えると、名前と実際が合わなくなる。
- **その場の翻訳で拒否された記事では、Translate を出さない（押せなくする）**：押しても断られやすい記事に、バッチの倍の料金を払わずに済むが、必ず断られるとは限らず、押す道がなくなる。

## 見直す条件

- 原文で読みたい記事が多く、切り替えを常に出すか、既定を設定で選べるようにしたくなったとき。
- オフラインで原文を読みたいことが多いとき（訳した本文と全文の両方を先に取るか）。
- 訳したタイトルや本文で探したいとき。
- 一覧で言語の枠の色が目立ちすぎ、未読やスターが見分けにくいとき。
- 訳したモデルと思考量を、記事を開く前に知りたいとき（一覧の行にも出すか）。ラベルが長く、読む画面の邪魔になるとき（系列の名前だけにするか）。ID の形が変わり、系列の名前と版に直せないモデルが増えたとき（直す形を足すか）。手元の古い記事でモデルが出ないことで、訳し直すかを決められないことが目立つとき（最初から同期し直させるか、開いたときに取る訳した本文の応答で埋めるか）。
- 日本語にしていない拒否の種類が目立つとき。その場の翻訳で拒否された記事で、Translate を押し直す人が多いとき。「そのほかの失敗」の 1 つの文では、読む人が Translate を押すかを決められないとき。
