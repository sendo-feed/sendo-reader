# 記事の翻訳

- 状態：提案中
- 関連：[ローカルファースト](local-first.md)、[UI とツール](ui.md)、[コンテナ版](container.md)、sendo の[記事の翻訳](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/translation.md)・[差分同期](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/sync.md)

sendo が日本語に訳した記事を、reader でどう見せ、どう訳してもらうか。何をいつ訳すか、訳文の状態、配り方は、sendo の[記事の翻訳](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/translation.md)と[差分同期](https://github.com/sendo-feed/sendo/blob/main/docs/decisions/sync.md)の 10 が正で、ここには書き写さない。

## 決定

### 見せ方

1. **一覧の行と記事の画面に、元の言語と翻訳の状態を 1 つのラベルで出す。** `EN · Queued`（バッチを待っている）、`EN · Translating`（その場の翻訳か訳し直しの最中）、`EN · Translated`（訳文がある）、`EN · Untranslated`（訳文がない）。
   - 言語は、sendo が配る ISO 639-1 を大文字にしたもの。状態は、差分同期で届いたものを手元の DB に置いて出す
   - 翻訳の項目が届かない記事（日本語の記事、Discord の投稿、API キーのない sendo、翻訳に対応する前の sendo）と、言語が判定できなかった記事（`und`）には、ラベルを出さない
   - 色で分けず、一覧の行のメタ（フィード名、時刻）と同じ控えめな文字で出す。一覧の行ではメタの並びに、記事の画面では見出しの下のメタの並びに置く
2. **一覧の行は、訳したタイトルがあれば、それを出す。**
3. **記事の画面は、訳文があれば訳文を先に出し、原文に切り替えられる。**
   - 訳文は、訳したタイトルと、訳した本文。訳した本文がなければ（sendo が本文を訳さなかった記事）原文の本文を、本文もなければ訳した要約を出す
   - 切り替えは、More actions の Show original ／ Show translation に置く。切り替えは開いている間だけで、手元の DB にも sendo にも置かず、URL にも入れない。記事を開き直すと、訳文に戻る
   - 原文の本文の出し方（全文、フィード本文、要約）は、[ローカルファースト](local-first.md)の「記事の本文」のまま

### 訳してもらう

4. **訳文のない記事は、記事の画面の Translate で、その場で訳してもらう。** 押したときだけ頼み、開いただけでは頼まない。
   - Translate は、状態が `queued` ／ `untranslated` の記事で、記事の画面のラベルのすぐ横に出す（ラベルのない `und` の記事では、ラベルの場所に出す）。翻訳の項目が届かない記事には出さない
   - 一覧の行には出さない（[UI とツール](ui.md)の 8）
5. **訳文のある記事は、More actions の Retranslate with Opus で、訳し直してもらう。** 状態が `translated` で、まだ訳し直していない記事にだけ出す。
   - 押したら、確かめの窓で「訳し直した訳文は、この記事を読むすべての人の訳文を置き換える」と伝え、選んでから頼む
6. **頼む操作は、sendo に届かないとできない操作にする**（[ローカルファースト](local-first.md)の 1 の例外）。
   - 操作キューには積まない。オフラインのときは、Translate と Retranslate with Opus を出したまま押せなくする
   - sendo が受け付けたら（202）、同期を頼み、状態が届くまで、手元ではラベルを `Translating` にして、押せなくする。訳し終えたことは、差分同期と通知で届く
   - 断られたとき（`translation_unavailable`、`translation_exists`、`retranslation_not_allowed` など）と、届かなかったときは、理由を日本語の文で出し、ラベルを手元の状態に戻す（`apps/web/src/lib/errors.ts` で文にする）
7. **キーボードの `t` で、訳文と原文を切り替える。** 訳文がなく Translate を出している記事では、Translate と同じ。操作の一覧（`?`）に足す。

### 手元に置く

8. **訳した本文は、原文の本文と同じく、記事ごとに取りにいき、手元に置く。**
   - `GET /api/v1/articles/{id}/translation` で取り、core で `ContentNode` の木にしてから置く（[ローカルファースト](local-first.md)の「記事の本文」と同じ守り）。原文の本文とは別の表に置き、記事を消すと一緒に消す
   - 訳した時刻が変わった（訳し直した）記事は、手元の訳した本文を捨て、次に要るときに取り直す
   - 手元に置く本文の量の上限に含め、上限を超えたときは、原文の本文と同じ順で消す
9. **未読の記事を先に取るとき、訳文のある記事は、全文の代わりに訳した本文を取る**（[ローカルファースト](local-first.md)の「記事の本文」）。選ぶ順と件数の決まりは変えない。原文に切り替えたときは、原文の本文をこれまでどおり取りにいく。
10. **訳したタイトルと本文は、手元の検索の対象にしない。** 探すのは、これまでどおり原文。

## 理由

- **ラベルを 1 つにし、色で分けない**：言語と状態を別々に出すと、一覧の行が混む。読む画面は没入感を優先し（[UI とツール](ui.md)の 8）、行に色の付いた印が並ぶと、未読やスターより目立ってしまう。状態は読めば分かれば足りる。
- **Translate をラベルの横に置く**：訳文のない外国語の記事を開いたとき、まず要るのが Translate で、要る記事にだけ出る。ラベルの横なら、何の操作かが状態と一緒に分かる。
- **訳し直しと切り替えを More actions に置く**：訳し直しは、品質が足りないときだけのまれな操作で、費用もかかる。原文への切り替えも、訳文で読むのが既定なのでまれ。どちらも常に出す操作にしない。キーボードの `t` は、見えるところでできることの近道にする。
- **その場の翻訳を自動にしない**：その場の翻訳は、バッチの倍の料金がかかる。開いた記事を自動で訳すと、バッチを待てば半額で済む記事や、訳さなくてよい記事にも払う。
- **頼む操作を操作キューに積まない**：ほかの操作と違い、手元に先に反映できる結果がない（訳文は sendo が作る）。オフラインで積んでおくと、あとで送ったときには、もうバッチで訳し終えていて、要らない料金がかかりうる。
- **訳した本文を先に取る**：訳文で読むのが既定なので、原文の全文だけを先に取っても、オフラインでは訳文で読めない。両方を取ると、本文を置く量の上限を倍の速さで使う。

## 検討した代替案

- **言語と状態を別のラベルにする、状態を色で分ける**：一覧の行が混み、読む画面の没入感を損なう。
- **訳文と原文の切り替えを、記事の画面の操作に常に出す**：訳文で読む間はほとんど使わず、操作が増える。
- **訳文か原文かの既定を、設定で選べるようにする**：使う人が少ないうちに設定を足すと、外しにくい。原文で読みたい人が多いと分かったら足す。
- **訳した本文と全文を、両方先に取る**：オフラインで原文も読めるが、本文を置く量の上限を倍の速さで使う。

## 見直す条件

- 原文で読みたい記事が多く、切り替えを常に出すか、既定を設定で選べるようにしたくなったとき。
- オフラインで原文を読みたいことが多いとき（訳した本文と全文の両方を先に取るか）。
- 訳したタイトルや本文で探したいとき。
